## 张淘然如何接接口

数据库为 `recruitment_dw_dev_cd_v1`。先读取当前构建表，再将返回的两个 build_id 固定为本次 Power BI 刷新的参数。不同机器重新构建时代理键可能不同，应查询取得实际编号。

```sql
SELECT source,batch_id,build_id,skill_denominator,
       body_hash_version,skill_text_scope,dictionary_version,rule_version,scope_version
FROM ads.current_analysis_builds;
```

本机当前返回腾讯 5、网易 6。通过 `audit.analysis_selection` 在一个事务中更新两源当前选择，历史构建可继续按 build_id 查询。

| 接口 | 使用方式 |
| --- | --- |
| ads.cd_job_detail | 固定 build_id，再按 is_core 筛选，读取正文及质量标记 |
| ads.cd_skill_evidence | 固定 build_id，筛 is_core 与 eligible_for_metric，核对字段、证据与版本 |
| ads.cd_skill_demand | 固定 build_id，直接核对本版技能出现数量及占比 |
| ads.cd_skill_pair | 固定 build_id，核对无序技能组合 |
| ads.cd_city / cd_experience / cd_education | 核心岗位的规范化维度分组，冲突单列 |
| ads.cd_overview | 每个构建的分母、范围、版本与问题数量 |

技能汇总视图是整个核心批次的基线。Power BI 加入城市/经验筛选时，应从同一构建的岗位和去重技能关系重新计算分子分母。历史两字段构建继续带原来的 skills-body-1.0 标记。
