# 连续观察采集安排

报告更新、PPT和录屏按用户要求暂缓。先完成当前四来源入仓和BI，再积累真实日期数据。本页是持续观察方案。2026-11-21已按用户要求启动四来源各约150岗的新批次；现已按用户选择注册每天11:18的Windows本机采集任务，首次11月22日；条件和暂停方法见[自动采集说明](自动采集任务使用说明.md)。

## 为什么需要重复采集

B01岗位方向、B02技能及组合、B03学历经验可在当前范围内分析。B04新增观察、持续未观察、内容变化需要可比的真实观察日期。至少两个可比日可算一次变化；建议先积累5—7个自然日，判断结果是否稳定。5—7天是项目建议，不是老师规定；一天重复运行不能补成多天。

当前事实粒度为发布号×北京时间批次结束日×来源岗位。保留来源身份及内容版本，跨日重复岗位属于新的观察，不是重复入库错误。分析一天的岗位结构时不能累计所有日期；分析多日观察量和期间不同岗位数时须分别命名。

## 每天按相同范围执行

1. 固定四家、渠道、城市/关键词条件、标题范围和解析版本。建议选择便于完成的固定晚间时段并预留网络时间，尽量让四家在同一个北京时间日期结束。实际时刻照录，不为凑同日修改时间。
2. 每家建立新batch，保留每次原始响应、请求时间、列表ID、总数、空页、重复页和错误。新一天不续写已accepted旧批；缓存重放也不计新一天。
3. 使用至少3秒请求间隔、有限重试及最大页数保护。验证码、401/403/418/429或限制提示立即停；不绕过限制。失败仍交partial批并说明原因。
4. 不把固定目标500条当作完整。需要原始分页终止及总数一致、未处理ID为零等证明，完整性由验收工具判定，不能人工改complete。
5. 对新批执行技术契约、21字段原始回放、范围审核和证据核对；新批独立生成policy及analysis目录，禁止复制本轮10条腾讯ID特例或照搬旧批冲突裁定。
6. 同规则新批加入新的发布输入集合，保留旧批。数仓先质量门、后原子切换；报表固定一次发布再刷新。旧四来源冻结配置继续用于回归，不自动发现并吞入新批。

2026-11-21新增`collectors.daily`与`public-pagination-2.0`。原采集器及旧分页证明保持原样，旧批次不追溯提升complete。新版四来源统一支持目标小批与`--until-exhausted`两种模式，至少3秒间隔、有限重试、原始响应和每次尝试时间均保留。京东即使小批提前结束或网络中止，也尝试读取count_end；遇限制则立即停止，不为取末次总数继续请求。网易前5条入选记录有实际详情核对，不称随机人工抽查。

在仓库根目录执行单一来源新批的例子：

```powershell
.\.venv-dbt\Scripts\python.exe -X utf8 -m collectors.daily --source jd --target 150 --max-pages 200
```

如确定要在同一公开范围遍历至末页，可选`--until-exhausted --max-pages 500`。此模式不会因target停止，但页数保护、网络失败或访问限制仍会停止。实际是否complete仍由原始总数、连续页、无重复/缺失ID及全部记录去向共同证明。新版查询及筛选配置有明确版本，与旧批默认不混成可比趋势。

## 什么时候允许显示变化

现有B04门要求：同一来源集、可比查询范围、相同规则版本，两个相邻真实日期都具备四来源完整覆盖。通过后才显示新增观察、持续未观察及内容变化；否则保持NULL和原因，不能将缺失补0。完整扫描仍有历时，只能称该采集窗口的公开岗位观察。

“新增观察”不等于企业新发布岗位；“持续未观察”不等于招聘关闭。官网发布时间也不能代替我们实际观察过的日期。某日partial可以用于当日已观察样本结构分析，不能用样本条数下降解释需求下降。

如果最终四来源无法持续完整，可保留B01—B03作为主要业务分析，并如实说明B04条件未成立。若决定另做某一家或一个稳定官方渠道的趋势，应先冻结新的独立范围、配置和分母，不能悄悄将当前四来源范围缩为两家并沿用原结论。
