## 电脑需要保持什么状态

11:18前开机、联网并保持当前用户登录。锁屏或只关闭显示器通常不影响后台采集；注销、关机时任务不能执行。睡眠、休眠会暂停或错过采集；本任务没有设置自动唤醒，也没有修改系统电源策略。建议插电，采集期间保持唤醒；结果生成后可以关机，不需要全天开着。

任务允许在错过时间且系统条件满足时补跑，但不能据此保证任意注销/关机后的补跑。应尽量在11:18前就绪。晚启动或跨日一律记录实际请求时间，绝不补造错过日期的观察。

## 运行内容与边界

四个来源各一个后台工作进程，每来源至少3秒间隔；在500页保护内尝试遍历至有效末页。总运行上限100分钟，网络有限重试，访问限制立即停止。总体耗时随来源岗位数和网络变化，不承诺每次全量。

Windows任务设置忽略并发启动，脚本另有文件锁与实际北京时间日期标记；每个实际日期最多自动启动一次。发生错误或超时会留下原始数据和状态，不静默重复整批。需要处理当日失败时，应先查看原因，再另建明确的补采批。

每批保留原始响应、请求时刻、代码哈希和动态观察窗口。结束后做结构/哈希自检，验收状态保留pending；完整性不足则partial。任务不会自动签字验收、修改正式发布、刷新Power BI或推送GitHub。新批应先复核再接入后续数仓版本。

原22:30的已验收批次加工任务保留，不替代这次新增的采集任务；冻结pipeline配置不会自动吸收新pending批。

## 查看结果和暂停

最新状态在仓库`.local/scheduled_collection/latest.json`；分来源日志与summary在`.local/scheduled_collection/runs/<实际时间>/`；数据在`data/<source>/<batch>/`。这些本机日志不提交Git。若任务完全无法启动，可在Windows任务计划程序中看上次运行结果；程序入口失败另存entry_failure.json。

在Windows任务计划程序中查找上述任务名，可查看、禁用、启用或停止。停止可能留下未完成批次，不应将其标成完整。需要命令操作时，在自己的PowerShell执行：

```powershell
Get-ScheduledTaskInfo -TaskName 'RecruitmentDW-Collect-FourSources-1118'
Disable-ScheduledTask -TaskName 'RecruitmentDW-Collect-FourSources-1118'
# 恢复：Enable-ScheduledTask -TaskName 'RecruitmentDW-Collect-FourSources-1118'
```

换电脑需安装Python依赖、复制完整仓库并在新机注册；只克隆Git不会自动建立Windows任务。入口是`scripts/register_collection_task.ps1`，采集参数在`warehouse/collection_schedule.json`。需要改时间时须同步任务触发器，单改JSON不改变Windows计划。
