# 仓内对象与字段字典

从主事实 `dwd.fact_job_daily` 及其维度/桥表开始阅读；ODS 和 AUDIT 为输入/支撑。下面为实际 SQL 元数据，不是未来计划对象。

核查库：`recruitment_dw_dev_expansion_v1`；69 个对象，608 个输出/持久列。相同字段跨对象重复计列，不以列数作为工作量结论。

PK 成员共同组成主键，不表示每列各自唯一。job_key 当前为来源岗位身份；build_id 为单来源提取构建，release_id 为整组日分析发布。未知维成员使用显式业务值及普通代理键，没有固定 0 键约定。

## 关键字段来源与转换

| 分析字段 | 来源与转换 |
| --- | --- |
| 日状态日期 | manifest.finished_at → Asia/Shanghai → date_key；不是源岗位更新时间 |
| 核心资格 | 已验收批次、冻结范围规则及冲突裁定 → is_core |
| 正文资格 | 职责、任职要求、补充要求至少一有效；旧构建按其字段范围保留原含义 |
| 标准类别 | 标题职业特征优先、源宽类别回退；原类别另存；规则见 normalization.py 与需求第2章 |
| 城市 | confirmed_locations_json + 冲突裁定 → 别名与省市查表；无法映射不猜测 |
| 有效技能成员 | 三字段证据同时筛核心/有效/正文资格，按日状态×标准技能去重 |
| 技能占比 | 有效技能覆盖的不同岗位数 / 对应完整正文集合；不是证据行数占比 |
| 原始证据 | source_revision、batch_id、raw_ref、文件/正文哈希、字段及字符位置逐级追溯 |

## ads.cd_city

每构建×确认地点/冲突/未知组一行；来自核心 cd_job_detail，按 observation_key 去重。未统一行政区划与市后缀；BI 另作展示归一，各城市计数不可相加。

定义与转换 SQL：[源码](../../dbt/models/ads/cd_city.sql)。业务含义以第 2、4 章为准；视图实际 SELECT 表达式是逐列转换依据。

| 字段 | SQL 类型 | 可空 | 键/引用 | 含义 |
| --- | --- | --- | --- | --- |
| `build_id` | bigint | 否 | — | 单来源批次的范围、冲突及技能分析构建；不是整组 release。 |
| `city_group` | nvarchar(MAX) | 是 | — | 城市/地点分析分组；冲突与未知单列。cd_city 保留确认地点原值；dual_city 使用历史有限别名规则。 |
| `posting_count` | bigint | 是 | — | 当前维度组覆盖的不同来源岗位数；技能或城市分组之间可能重叠。 |
