本次已从 Olist 的 Kaggle 公开发布接口下载完整 ZIP，原始数据保存在 `data/raw/`，压缩包保存在 `data/downloads/olist.zip`。两处数据均在本机保留，已配置 Git 忽略规则。无需手工修改原始 CSV。

## 复现方法

需要 Python 3.11 及以上和 pandas。建议在项目虚拟环境中安装 `scripts/requirements-data.txt`，避免影响其他项目。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r scripts/requirements-data.txt
.\.venv\Scripts\python.exe scripts/download_olist.py
.\.venv\Scripts\python.exe scripts/audit_olist.py
.\.venv\Scripts\python.exe scripts/verify_olist_audit.py
```

下载脚本在已有压缩包时检查并复用，不重复下载，不覆盖不同内容的原始文件。若下载网络不通，可将从同一 Kaggle 发布页取得的原包保存到 `data/downloads/olist.zip` 后再运行；不得混入第三方清洗后的文件。

`audit_olist.py` 退出码 0 表示无阻断项，2 表示检查完成但仍有阻断项。数据解析或结构异常会报错退出。当前缺少支付记录的事实没有被修复，返回非零是预期行为。独立核验脚本返回 0 表示报告的数字与原始 CSV 一致，不表示所有业务质量问题都已关闭。

## 下一步如何处理

1. ODS 原样接收 9 表，保留原值及批次信息。不要删除缺失支付的订单或填造支付金额。
2. 在 DWD/DWS 保留该订单并标记 `payment_missing`。商品金额、订单数与履约指标仍按各自有效集合统计。涉及全量支付的指标暂不发布；若改为“已记录支付金额”，同时展示记录覆盖率并更新指标字典。
3. 每订单选择一条代表评价，原始全部评价继续保留。地理表去重、按邮编汇总后再关联。
4. 8 笔已送达但缺少到货时间的订单不进入配送耗时和逾期率分母，其他业务事实仍保留。
5. 数据库实现后，用本次源数据金额和样本数作为基准，逐层检查 ODS、DWD、DWS、ADS；本次未进行数据库层间验收。
