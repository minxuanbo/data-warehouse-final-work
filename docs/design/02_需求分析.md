## 2.2 范围与分类决策

地域为中国大陆可识别城市，不限制单一地区。初始来源为腾讯、网易官网；额外来源先验证再审批。保留招聘类型原代码；网易官网已核实workType：0全职、1实习、2派遣，腾讯代码未释义。不得将全职自动解释成社招，也不把实习等同校招。薪资不作为本期必要分析。

核心范围按冻结的 `warehouse/cd_policy_v12.json` 及原批次裁定执行，两个联调批次各 98 核心岗；扩展记录保留，指标筛 `is_core=true`。新批技术验收和范围审核不可通过改标志自动完成。

**标准岗位类别的自动初分类规则**：使用岗位标题的明确职业特征，依次识别算法/AI、数据开发/分析、测试、运维/安全、开发，再用官网宽类别回退；仍不能识别为“待分类”。正文用于核对和处理歧义，不采用正文中技能词出现次数投票。分类版本和证据需保留。这个定义替代原“职责优先”但未实现的表述；程序输出称自动初分类，不宣称人工准确分类。

源类别始终单列为 `category_raw`，标准类别为 `category_group`（快照接口）。历史小批接口保留源类别，BI 字段明确叫 `source_category_group`，不与标准类别混名。

`category_group`在本期解释为**按优先级互斥归属的自动主方向**，不是独立的职业职能分类或人工裁定。例如“大模型后端研发”命中大模型规则而进入算法/AI，“大数据组件运维”进入数据方向；conformed-cn-1.2以有英文单词边界的AI、AIGC及人工智能/机器学习/深度学习等显式词补齐主方向识别。因此不能把“开发”和“算法/AI”解读成纯开发职能与纯算法职能的比较。本轮已对全部200岗执行AI辅助标题与规则审计，并保存版本及来源证据；这不等于独立人工分类准确率。职能/领域拆分若成为新需求，再另行设计验证。[当前复核与分工](../小批联调后续计划与四人分工.md)说明责任与交付。

## 2.2.1 学历与经验的派生口径

门槛规则版本 `qualification-cn-1.1`，快照规范化版本 `conformed-cn-1.2`。经验将“三年以上工作经验”忠实规范为“3年以上”，保留原字段与证据，不改变年限边界；原值存在但不能识别为“待解析”，不是不限。

学历先读取明确的结构化值，再核对任职/补充要求中的学历表述；结构化值缺失时，从正文提取明确要求。不同学历备选取最低明确选项；“本科及以上，硕士优先”保留本科门槛和硕士偏好；只有偏好则硬性学历为“未注明”。含放宽等复杂条件为待确认，来源与正文不一致单列冲突，不静默选一边。没有披露不等于不限，只有明确“不限”才进入不限组。

派生结果不写回 education_raw/experience_raw。日状态关联 `dwd.job_qualification_evidence`，按发布保留值、解析状态、原字段、逐字证据、Unicode位置、规范记录定位和所有原响应引用。历史版本保持原样。当前腾讯核心98岗学历为本科36、硕士12、未注明50（其中2岗仅有偏好）；经验原93条未映射已消除，3条冲突继续保留。

## 2.3 时间与身份

- 来源身份为 `(source,source_job_id)`，长 ID 保持文本，不按标题去重。
- 观察事实的一行是某批次对一条来源身份的观察。
- 日快照的一行是固定发布版本内、某个北京时间批次结束日的一条来源岗位状态。`job_key` 当前一对一对应来源身份，不表示跨来源归并已经完成。
- 形式上按每日选择批次，但只有真实提交的观察才形成数据。不造缺失日期，不把重复加工旧批次当新采集。
- sample 通道允许验收后的 partial 样本；formal 要求批准的每来源范围完整。两通道含义及选批规则见第 4 章。

## 2.4 指标集合与可加性

令 J 为固定发布版本、日期与来源范围内筛选后的不同核心来源岗位；T 为 J 中职责、任职要求、补充要求三字段至少一个有效的岗位集合；E 为有效技能证据去重后的岗位×标准技能集合。

| 指标 | 定义 | 汇总规则 |
| --- | --- | --- |
| 核心岗位数 | 不同 J 岗位数 | 单日、互斥类别可加；跨日同岗重现应去重，不能累计为独立机会 |
| 正文分母 | T 的不同岗位数 | 不从技能桥求分母 |
| 正文覆盖率 | 正文分母 / 核心岗位数 | 比率重算，不平均各组比例 |
| 技能岗位数及占比 | 对指定技能，E 中不同岗位数 / 正文分母 | 技能选择不反向缩小正文分母；无命中岗位仍在 T |
| 技能组合岗位数及占比 | 同时含两种指定技能的不同岗位数 / 正文分母 | 技能对按固定顺序去重；总计不是各行之和 |
| 城市岗位数 | J 中含所选城市的不同岗位数 | 多城市取并集，分组之和可以超过全局 |
| 学历/经验分布 | 各门槛组的不同岗位数 / J | 未知、不限、冲突分开；不能把缺失当无要求 |
| 观察变化 | 同范围、同规则、相邻完整日的集合差及内容哈希变化 | 不等于企业新发布或确认关闭；条件不满足为 NULL |

零分母返回 NULL/BLANK。强度“必需/优先/明确提及”可进入技能统计；否定与不确定只留作审计。历史两字段构建维持原口径，不混入当前三字段结果。

## 2.5 数据交付与质量要求

采集契约仍以[小组采集规范](../小组项目说明与采集交付规范.md)和 [data 提交入口](../../data/README.md)为准，不复制第二份字段表。提交原始响应、规范 JSONL、批次清单、请求日志及质量问题；同批 ID 唯一、哈希匹配、带时区、原始引用完整。技术验收 accepted 不等于覆盖 complete。

离线重跑不得重复入账；规则变化形成新版本，失败不移动发布指针。另一环境应能从固定输入重建，并得到相同岗位/技能指标。查询性能只在实测规模声明，不把 200 岗测试扩大为万级容量承诺。

每来源已存在的20岗参考继续保留。当前人工复核包总计100个不同来源岗位，每来源50个，包含原参考40个、新增60个；整包仍需真实人工提交，不能表述为额外100岗已审。生成复核包或AI程序核对不能冒充人工完成。没有连续完整日时，B04保留受限状态，不因此否定B01—B03的样本分析。
