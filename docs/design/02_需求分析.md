# 2. 需求分析

[设计目录](README.md) · 上一章：[项目背景](01_项目背景.md) · 下一章：[概念设计](03_概念设计.md)

## 2.1 范围基线

| 项目 | 本版决定 | 处理边界 |
| --- | --- | --- |
| 地域 | 中国大陆所有可识别城市，不只采一个地区 | 海外排除；地点缺失标记未知，不用于城市排名；混合大陆/海外多地点只保留大陆关联并记录原值 |
| 岗位类别 | 开发、测试、数据开发/分析、算法/AI、运维/安全 | 每岗位一个主类别；按职责优先于名称分类，歧义人工审核；游戏美术、纯销售、纯产品/非技术项目管理排除 |
| 招聘类型 | 社招、校招、实习分组保留 | 未知单独展示，不擅自译码；实习不直接与社招薪资比较 |
| 来源 | 腾讯、网易为初始范围 | A/B 各验证一个额外企业官网；新增来源改变 scope_version，前后不可直接算增长 |
| 时间 | 建议每日 22:30（Asia/Shanghai）启动；首轮目标连续 14 天 | 起始日由设计审核后确定；不能从更新时间倒推历史快照；少于两天不计算变化 |
| 规模 | 首批各 100 个不同来源 ID 用于联调，之后覆盖批准范围的可访问页面 | 不把接口总数等同于实得数；不承诺未经实测的条数、全站覆盖或历史补采 |
| 记录类型 | 核心分析为可识别的单一岗位 | 综合招聘简章保存并标记，排除于单岗指标；不将整篇招聘人数分配到某个岗位 |

## 2.2 功能需求与验收

| 编号 | 需求 | 验收依据 |
| --- | --- | --- |
| F01 | 多来源列表、分页和必要详情采集 | 保存源 URL、真实响应、请求时间、业务状态；验证多页 ID 不完全重复 |
| F02 | 统一字段契约和原始证据 | JSONL 可解析；必填键完整；长 ID 保持字符串；哈希全部一致 |
| F03 | 岗位分类、企业和地点规范化 | 原值与规范值并存；别名、歧义、未知可追溯；每岗主类别唯一 |
| F04 | 来源内去重和跨源谨慎归并 | 同批次 `(source, source_job_id)` 唯一；跨源合并有证据、规则版本与人工复核记录 |
| F05 | 观察快照与版本变化 | 当日多批只选择一个合格源批次；规则变化可重建，不覆写原始观察 |
| F06 | 技能提取 | 保存词典版本、证据片段、匹配位置、必需/优先/提及/不确定标签；人工标注验证 |
| F07 | 岗位结构、门槛、技能与变化指标 | 每指标有粒度、集合、分子分母、时间和缺失策略；ADS 与独立 SQL 对账 |
| F08 | 筛选与下钻 | 日期、企业/来源、城市、主类别、招聘类型、学历/经验；明细可回查原始岗位 |
| F09 | 质量与审计 | 失败、缺失、冲突、样本覆盖和归并情况可查询；失败批次不能驱动下架判断 |
| F10 | 重跑、发布和复现 | 同一批次及规则重跑不重复入账；发布失败保留上一可用版本；另一组员从约定批次复现 |

## 2.3 指标口径

对日期 d 和固定来源范围 S，选择每个来源在北京时间该日结束的最后一个完整且验收合格的批次。该日期是**批次结束日**，不是岗位发布日期；扫描是一个时间区间，不宣称瞬时全量状态。缺少某来源时该范围标为不完整，允许查阅带提示的覆盖样本，不发布可比变化率。

P(d,S) 为上述批次中范围内的不同来源岗位；J(d,S,V) 为在同一归并、分类和技能规则版本 V 下归并后的岗位集合；每个岗位的属性来自一条确定的代表来源版本。选择顺序：可核实直接雇主官网优先，其次批准的来源优先级、观察时间降序、来源代码及来源岗位 ID 升序。不能逐字段挑选不同来源而制造一条实际不存在的岗位描述。

| 指标 | 公式/粒度 | 缺失与限制 |
| --- | --- | --- |
| 来源发布记录数 | `COUNT DISTINCT(source, source_job_id)`，在 P 内 | 不叫独立招聘机会数 |
| 当日归并岗位数 | `COUNT DISTINCT job_key`，在 J 内 | 是经过保守归并的样本数，可能仍有未识别重复 |
| 技能覆盖率 | J 中有可解析职责/要求正文的岗位数 / J 数量 | 分母为零返回 NULL；同时展示两项计数 |
| 技能出现占比 | 有该技能有效证据的不同岗位数 / 有可解析正文的岗位数 | 以代表版本为准；默认含必需/优先/明确提及，排除否定与不确定；分别提供要求强度筛选 |
| 技能组合岗位数 | 同时满足两个指定技能的不同岗位数 | 同一岗位同技能只计一次；不把多个技能出现次数当岗位数 |
| 学历/经验分布 | 每组不同岗位数 / J 数量 | 未知、冲突单独成组，不当“不限”；显示覆盖率 |
| 城市岗位数 | J 中包含该大陆城市的不同岗位数 | 一个岗位可出现在多个城市；城市数之和可能大于全局，不画可加总占比饼图 |
| 首次发现岗位数 | 在固定 S、V 及观察窗口内首次出现的 job_key 数 | 第一天为基线，不当作新增招聘；名称必须为“首次发现” |
| 当日新增观察数 | `J(d) - J(d-1)` 的集合大小 | 仅相邻两日范围完整、S/V 相同；可能是恢复可见，不等于企业新发布 |
| 持续未观察数 | 曾出现且连续两个合格日未观察到的岗位数 | 表示观察状态，不称确认关闭；任一天扫描不完整则不累计连续缺失 |
| 内容变化岗位数 | 两日都存在且代表版本规范化内容哈希不同的岗位数 | 规则和代表来源切换导致的变化另行标记，不解释为企业修改 |
| 薪资区间分布（可选） | 去重、明确披露同币种同周期薪资的子集，分别分析上下界 | 面议/缺失排除且披露覆盖率；区间中点不得称实际平均收入 |

日岗位快照不可跨日期求和当作独立岗位数。日期区间查询应按 job_key 去重；比率跨组汇总需重新求分子分母，不能平均比率。招聘声明人数可能“若干”、转载重复或属于综合简章，首版只展示原文，不作为核心总需求人数 KPI。

## 2.4 采集契约 v1.0 候选与交接

统一 JSONL 字段定义以[小组说明第 5 节](../小组项目说明与采集交付规范.md)为唯一字段表，本章规定其业务约束，不复制第二套格式。必须包含 `source`、字符串 `source_job_id`、`batch_id`、带时区 `observed_at`、`source_url`、原始标题/企业、地点数组、职责/要求及原始文件引用；其余键存在但未提供的值填 null。来源时间按原值保存，不能代替采集时间。

批次清单另须包含 `scope_version`、`query_spec`（分类/地域/关键词/端点）、起止时间、预期分页依据、实际页数、唯一 ID 数、错误页、`coverage_status`（complete/partial/failed）、采集器和契约版本。complete 仅指该批准查询范围遍历完成且通过业务响应检查，不保证网站覆盖整个市场。若 API 限制可见页数或总数不一致，不能静默标 complete。

单源每次运行生成独立 batch_id；同批次重复 ID 只输出一条规范记录，原始请求仍保留。详情失败时不能保留旧职责伪装成当前内容：标记缺失及批次质量，按策略决定是否允许降级。原始文件放共享数据目录，Git 管理代码、说明、清单和必要少量样本，不管理大批正文或凭据。

固定范围、契约、接入验收经过四人审核后标记 v1.0；此时才开始正式小批交付。小批验收通过后扩量与数仓开发并行。现有 108 条试采样本是探索格式，需要映射，不能直接视作契约通过。

## 2.5 质量与非功能要求

| 项目 | 目标（不是实测结果） | 失败处理 |
| --- | --- | --- |
| 必填键、哈希、同批唯一性 | 100% 通过 | 隔离不合格记录/批次，不发布正式快照 |
| 记录可追溯 | 每条观察能定位响应文件、源 ID、解析版本 | 阻断对应批次 |
| 人工字段检查 | 每来源首批至少 20 条，覆盖类别与异常；核心 ID/标题/正文不能错配 | 修解析器，重验后交付 |
| 技能提取验证 | D 建至少 100 条人工核对样本，区分调规则集与留出集；留出集精确率目标≥90%、召回率≥80% | 未达标调整词典或缩小技能范围，披露实际结果，不冒充精确分类 |
| 查询性能 | 约定验收数据量下，常用查询预热后测 3 次，单次目标≤3 秒 | 保存查询计划并优化；不能据此承诺并发 SLA |
| ETL 性能 | 1 万来源岗位/日、14 日的容量假设下，单批仓内加工目标≤10 分钟 | 实测报告配置/规模/耗时；采集网络耗时单独统计 |
| 失败与恢复 | 校验失败保留上一发布版本；可从原始批次及规则重建 | 记录失败运行，不将旧结果伪装成当日成功 |
| 可复现 | 锁定 Python/dbt 依赖、数据库及驱动版本、代码、数据清单和规则版本 | 禁止仅靠个人电脑隐含配置 |

对明确未提供的薪资不设伪造补齐目标。采集单并发、默认间隔至少 3 秒；网络超时可有限重试并退避，登录/验证码/访问限制停止。高并发和绕过限制不属于本项目需求。

## 2.6 四人责任接口与需求追踪

A：腾讯及新增来源、采集编排；B：网易及新增来源、批次质量；C：模型、ETL 和发布；D：技能、指标与看板。设计共同审核，不将全部文档压给 C 或 D。

F01/F02→ODS 与采集审计；F03/F04→一致性维度、岗位版本及归并映射；F05→观察事实与每日快照；F06→技能证据桥表；F07/F08→DWS/ADS；F09/F10→质量结果、版本发布和恢复。最终以小批、集成及答辩三次验收形成证据，实际日程见小组任务看板。
