# 7 多维分析与可视化

[设计目录](README.md) · [上一章](06_系统实现.md) · [当前验收](../verification/课程整改与答辩逐项核查.md)

## 7.1 业务分析而非表结构展示

分析围绕 B01 岗位结构、B02 技能需求、B03 岗位门槛、B04 有条件的观察变化。真实数据查询生成的[主题分析结果](../../reports/analysis/岗位需求主题分析.md)保存范围、分母、计数、解释与局限；它是本项目面向主题的分析成果，质量测试和维表数量不替代该成果。

## 7.2 Power BI 入口与口径

工程为 `dashboards/powerbi/Recruitment.pbip`。报表保留七页，角色清楚区分：

| 页面 | 业务用途 | 取数范围 |
| --- | --- | --- |
| 01 小批概览 | 来源样本及学历/经验结构 | 固定 CD 构建；类别明确为来源原类别 |
| 02 技能与组合 | 技能覆盖及组合训练依据 | 同一固定 CD 正文集合，不用证据频次代岗位数 |
| 03 岗位与证据 | 从小批数字回到真实原文 | 固定 CD 身份和证据 |
| 04 构建与质量 | 判断范围、规则和字段冲突 | 构建审计 |
| 05 项目质量 KPI | 判断交付数据可信度 | 构建级质量，不随岗位城市筛选改变 |
| 06 岗位需求多维分析 | 标准方向、地区、日期及门槛交叉 | 固定 release 的日状态星型投影 |
| 07 快照岗位与证据 | 从第 06 页类别钻取到岗位、学历/经验依据及技能证据 | 同一固定 release |

CD 页保留已验收的技能/范围基线，学历与经验投影显式关联当前固定的门槛 release；快照页提供标准分类和日期层次。两套投影不通过正文或事实明细直接相连；日期/来源及技术版本各自明确。源类别和标准类别不能用同名字段暗示可直接比较。

## 7.3 OLAP 操作与业务意义

- 切片：限定腾讯来源，查看其岗位和技能结构。
- 切块：限定地区、标准类别和门槛的交集，重新计算岗位集合及正文分母。
- 下钻/上卷：沿年→季度→月→日、省→市展开收起；不同日期数据可展示，但当前不能解释为完整趋势。
- 旋转：交换类别和地点的行列，从两个角度看同一岗位集合；总计按岗位并集。
- 明细探取：在第 06 页某类别总计右键钻取至第 07 页，选岗位查看原文证据并返回。

使用 SQL/DAX 表格语义模型，没有部署 SSAS 多维立方体，不将 DAX 称作 MDX。矩阵能展开不等于连续日覆盖已满足。

## 7.4 语义模型与计数规则

模型关系按明确身份键单向传播，城市多选通过岗位集合 TREATAS 回传，技能筛选不缩小正文分母。来源岗位 ID 是文本。原始正文是内容载荷，不是关联键；禁止 `content_json` 双向关系和自动推断事实间关系。保留显式日期维，关闭自动关系检测及自动日期对分析模型的干扰。

当前基线核心分母 196，有效岗位×技能 667，至少一种技能覆盖 163 岗，至少一个技能组合覆盖 139 岗；表格总计不是各行相加。快照跨日岗位数以稳定 job_key 去重，日状态行数与独立岗位数分别解释。

## 7.5 验收与结论边界

必须同时验证数据库口径、当前 PBIP 静态关系、当前加载模型及 DAX 用例。文件哈希与测试记录绑定；编辑/刷新/保存后的模型变化不能沿用不匹配的旧记录。图形交互验收需标明是本轮执行还是带日期的用户确认，不将 SQL 成功当作界面成功。

当前分析只描述腾讯、网易两个部分样本，且观察日不同。类型代码未核实、部分门槛未知/冲突、分类为自动初分类，均在结论中披露。连续完整真实批次、额外人工技能复核属于后续数据验收条件，不通过改旗标或生成测试样本伪装完成。
