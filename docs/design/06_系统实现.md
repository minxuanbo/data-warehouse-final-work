# 6 系统实现

[设计目录](README.md) · [上一章](05_物理设计.md) · [下一章](07_多维分析与可视化.md)

## 6.1 开发工具和部署平台

实际采用 Windows、Python 3.12、SQL Server 2025、ODBC Driver 18、SSMS、dbt Core 1.12.6、dbt-sqlserver 1.12.1 与 Power BI Desktop。Python 处理网络响应、契约校验、参数化持久写入；SQL Server 执行仓内查询；dbt 管理依赖、测试和模型文档；Power BI 进行 Import 模式的主题分析。使用新工具的理由是可测试和可复现，不以工具数量替代模型质量。

## 6.3 ETL

当前单入口见 [仓内运行说明](../../warehouse/README.md)。流程为准备固定/新验收批次 → 文件和契约校验 → ODS 原值 → 身份/内容版本/观察 → 三字段技能与范围/冲突增强 → 日状态和维度/桥 → dbt 主题汇总及质量门 → 原子发布 → 固定版本分析。

| 转换 | 输入与规则 | 输出与可核查内容 |
| --- | --- | --- |
| 原始接入 | manifest、jobs、raw、SHA-256；ID 文本、同批唯一 | ODS 与批次审计；不合格即失败，不静默丢行 |
| 内容历史 | 岗位属性哈希及观察时间；A→B→A 不合并区间 | dim.posting_version 与来源观察 |
| 正文与冲突 | 职责、任职要求、补充要求；源值和裁定分开 | build 内增强、三字段正文分母、冲突分组 |
| 技能 | 词典别名、边界、否定/优先语境；按岗位技能去重 | 有效技能桥和全部审计证据；字段、片段、位置和版本可回查 |
| 分类/规范化 | 第 2 章初分类规则；地点别名与省市；未知不猜 | 标准维度、来源原值和规则版本 |
| 学历/经验派生 | 中文经验年限规范化；来源/正文核对；必需与优先分开 | 规则1.0、快照规范化1.1；门槛证据视图、冲突及未注明分组 |
| 日状态 | 每来源结束日选一批；固定身份和规则 | release/date/job 唯一；多值城市/技能桥 |
| 汇总与服务 | 先岗位集合、后分子分母；完整性门控制变化 | DWS 主题汇总、ADS 与 Power BI |

真实例子：腾讯岗位 2072607372890783744 的 ImportantItem 补充要求出现“深度定制化开发Unity引擎优先”。接入到 `additional_requirements_raw`，Unity 保留为“优先”，同时保留原响应路径、哈希和字符区间；不会将“优先”改写为“必需”。

## 6.4 数据分层

第 4 章的分层图对应实际对象：ODS 原值，DWD/DIM 观察历史与日状态星型，DWS 主题计数/分母，ADS 业务查询与证据。`audit.collection_batch` 等负责技术审计，不按表名数量虚构业务事实。所有 dbt 输出是视图，持久写入与约束由版本化 SQL/Python 管理。

模型/字段含义、来源、转换和粒度见 [对象字典](../reference/仓内对象字典.md)及 dbt YAML。每个发布固定 release_id；历史 CD 小批固定 build_id。调用者不能无条件累计所有历史发布。

## 6.5 KPI

岗位技能占比等为主题分析指标，不随意编造“越高越好”的经营目标。当前三项具有目标/责任/状态的 KPI 是**项目数据质量 KPI**，接口 `ads.cd_quality_kpi`，目标版本 `project_acceptance_v1`。

| KPI | 分子/分母 | 目标与责任 | 当前固定批次 |
| --- | --- | --- | --- |
| 核心岗位正文覆盖率 | 有效正文核心岗位 / 核心岗位 | 100%，C/D | 每源 98/98 |
| 来源岗位原文可追溯率 | 可定位 URL、原文件/哈希及 Git 修订的岗位 / 来源岗位 | 100%，A/B/C | 每源 100/100 |
| 批准范围遍历完成率 | 完整批次指示值 / 1 | 100%，A/B | 每源 0/1，partial，不达标 |

有分母且达目标为 +1，未达为 -1，无分母为 NULL；没有依据不设置黄灯或综合权重。无可比日序列时趋势 NULL，不能画持平箭头。质量 KPI 已有报表页，但业务主题仍由岗位、门槛、技能分析体现。

最新运行、测试、复现和待满足的数据条件统一见[整改验收](../verification/课程整改与答辩逐项核查.md)，不把本章设计说明当作每次运行结果。
