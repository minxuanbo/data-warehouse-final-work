## 5.1 部署与职责

Windows 本机部署：Python 3.12 采集/校验/入库 → SQL Server 2025 保存和执行 → dbt Core 1.12.6 + dbt-sqlserver 1.12.1 组织 T-SQL 转换/测试 → Power BI Desktop Import 分析。SSMS 管理数据库，ODBC Driver 18 使用本机 Windows 身份；任务计划程序只启动已验收批次的加工，不代替采集、技术审核或 BI 刷新。

初次复现需要创建专用开发库权限；脚本只使用 `recruitment_dw_dev*` 库。默认 `lpc:localhost` 是本机共享内存，不是连接组长电脑；不同机器使用各自实例。锁文件位于 `warehouse/requirements.lock.txt`，操作见 [仓内说明](../../warehouse/README.md)。

## 5.2 实际 DDL 与关键对象

| DDL | 实际职责 |
| --- | --- |
| `sql/001_trial_schema.sql` | 六类 schema、ODS、批次审计、来源身份、内容版本、观察及原地点桥 |
| `sql/002_cd_schema.sql` | 单来源分析构建、范围/冲突增强、技能与证据桥 |
| `sql/003_skill_body_versions.sql` | 三字段正文和提取版本元数据 |
| `sql/004_release_schema.sql` | 标准描述维度、日状态事实/桥、release 输入与发布控制 |
| `sql/005_qualification_evidence.sql` | 按release×日×岗位保存门槛派生与JSON证据；不覆写原始观察 |

持久对象由幂等迁移维护，dbt 模型使用 view，不通过重建持久表丢失历史、代理键或外键。实际字段、来源转换与模型说明由 dbt YAML 和[仓内对象字典](../reference/仓内对象字典.md)集中维护；本章说明主设计约束。

## 5.3 键、类型与完整性

| 对象/字段 | 实际设计 | 业务原因 |
| --- | --- | --- |
| 来源身份 | BIGINT posting_key；UNIQUE(source,source_job_id) | 长 ID 为 NVARCHAR(200) BIN2 文本，跨来源不比较裸 ID |
| 内容版本 | BIGINT version_key；来源身份外键、观察有效期、payload JSON | A→B→A 保留三段历史；CHECK(to>from) 与单个当前版本唯一索引 |
| 来源观察 | BIGINT observation_key；UNIQUE(batch_id,posting_key) | 同批重复请求不产生重复事实；版本/身份组合 FK 防串岗 |
| 日期维 | `dim.calendar_date`，INT date_key 与 DATE 唯一 | 年季度月日存同表；分析日不是加载时间 |
| 日事实 | PK(release_id,date_key,job_key)；各维外键 | 固定发布×日×来源身份；job_count CHECK=1，核心/正文 bit 标志 |
| 城市/技能桥 | 日事实复合键加维键组成 PK/FK | 多值成员去重，避免放大计数 |
| 描述维度 | BIGINT IDENTITY，业务值唯一或带规范化版本唯一 | 规范成员可复用；未知为显式业务成员，无固定 0 键假设 |
| 正文与证据 | NVARCHAR(MAX)、ISJSON、SHA-256、相对路径 | 保留 Unicode 长文本、原始语义及回溯证据 |
| 观察/审计时间 | DATETIMEOFFSET；来源时间保留原值 | 带时区；加载时间不冒充发布日期 |
| 发布指针 | PK(channel)，FK release_id；sample/formal | 分通道发布，无 singleton 单行假设 |

## 5.4 索引、存储与规模

来源身份唯一键、当前版本唯一索引、观察身份/时间索引支撑回查；日事实有 `(release_id,source_key,date_key)` 索引并包含核心、正文、类别，技能桥有反向技能索引。使用行存和显式索引，首版不分区，不因课程选题强行采用列存或分布式组件。

规划容量假设仍为 1 万来源岗位/日×14 日；这不是当前实测。当前性能和恢复记录仅覆盖真实 200 岗样本。扩大容量声明前，需记录硬件、行数、正文/索引/日志大小、三次查询及批处理耗时。缺少实测不写成已达到 SLA。

## 5.5 事务、版本与失败控制

批次按 ID 和输入哈希幂等，变化的同名批次拒绝覆盖。内容/观察写入事务，应用锁防并发重入。技能按输入及规则版本形成单来源 build；日状态固定 release 输入、代码、规范化及映射指纹，旧发布不可原地改写。

dbt 多模型构建不是整个流水线单事务。新快照先构建、后质量检查，短事务复查 ready 状态后切换通道指针；失败不切换。报表全部导入查询固定同一 release 或明确的历史 CD build 集合，禁止正文连接两套事实。

## 5.6 访问、备份与调度

开发环境使用 Windows 身份，可由同一开发账号完成课程链路；这不等于生产环境权限隔离已经验收。凭据、数据库文件、备份及本机缓存不提交 Git。组员原始采集批次仍按 data 规范提交 Git，不忽略整个 data 目录。

已存在 2026-11-17 的 BACKUP/新库 RESTORE 及哈希/指标对账记录。本轮复现使用新开发库从固定输入重建，不把程序重建当物理恢复。跨磁盘容灾和生产 RPO/RTO 没有实测，不作承诺。

计划任务注册入口 `scripts/register_pipeline_task.ps1`，以当前用户登录态每日 22:30 执行已验收批次加工；不采新数据、不自动批准待审核批次、不保证未登录或关机时执行。调度、数据持续覆盖和分析变化是三个不同的验收项目。
