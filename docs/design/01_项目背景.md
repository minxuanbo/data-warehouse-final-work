# 1. 项目背景

[设计目录](README.md) · 下一章：[需求分析](02_需求分析.md)

## 1.1 行业背景与问题

企业通过各自招聘官网及就业平台发布岗位，求职者可以查到单条职位，却难以对不同企业、地区和岗位方向形成一致比较。名称相似的岗位可能要求不同技能；相同岗位可能经多个高校或平台重复发布；学历、经验和地点的表达也不统一。直接累计网页条数或用关键词搜索结果数量衡量需求，会产生偏差。

本项目建设面向数字技术岗位的离线数据仓库，通过自主采集、统一口径、分层处理和持续快照，将分散的公开岗位信息转换为可追溯的分析数据，支持求职准备、就业指导及技术人才需求观察。核心价值不是再做一个招聘搜索网站，而是回答跨企业、跨地区、跨技能及跨观察日期的问题。

## 1.2 服务对象与决策价值

| 服务对象 | 当前困难 | 数仓支持的决策 | 不应推导的结论 |
| --- | --- | --- | --- |
| 学生与求职者 | 不清楚岗位技能组合和学历经验门槛 | 比较岗位类别、技能组合及地区，制定学习与投递方向 | 掌握某技能一定能入职或获得某薪资 |
| 就业指导人员 | 各渠道信息分散、转载影响数量 | 观察样本企业需求结构，筛选适合毕业生的岗位方向 | 用少数企业代表全国就业率 |
| 课程与培养方案讨论者 | 技术要求缺少整理后的证据 | 将技能需求与课程内容做人工对照，作为讨论依据 | 仅凭招聘频次取消或增设课程 |
| 项目开发与数据维护者 | 来源变化、重复与缺失难定位 | 用覆盖率、质量和血缘确定哪些结果可发布 | 请求成功就意味着数据完整 |

示例：比较“数据开发”与“算法/AI”岗位的技能要求时，先限定相同观察日期和来源范围，排除综合简章并处理转载，再以具有有效正文的岗位作为技能占比的分母。这样的结论才比直接搜索两个关键词的结果数更可靠。

## 1.3 选题依据与已有证据

2026-10-29 至 10-30 已开展真实小规模试采。腾讯、网易的列表、第二页、第十页和抽样详情能够读取；保存 108 条来源岗位记录及 9 个详情/简章验证结果。国家大学生就业服务平台的前两页及详情可读，但第十页要求登录，只列为补充来源。具体请求、成功条件和局限以[试采报告](../../research/recruitment/README.md)为准。

试采已发现同一公司同岗经不同高校转载、网易结构化学历与任职正文不一致、综合招聘简章混入单岗列表等问题。这些问题提供了真实的去重、字段冲突、粒度建模和数据质量工作，不需要构造模拟岗位增加工作量。

“采集工作量”由可复现的多来源适配、分页及详情读取、时间调度、异常处理、增量观察和原始证据管理体现；“数仓工作量”由一致性维度、事实粒度、归并、技能关联、快照、分层对账和可视化体现。不能以重复数据条数或绕过网站限制证明工作量。

## 1.4 项目目标与成功标准

1. 形成从公开岗位页面/接口到分析看板的完整可复现链路。
2. 每个公开指标能够解释样本范围、日期、规则版本和分母，并可回查原始岗位。
3. 能识别来源岗位与实际归并岗位的差别，避免同一岗位多地点、多技能或转载产生重复计数。
4. 使用真实连续观察快照分析首次发现与持续未观察到的变化，不虚构历史发布与关闭事件。
5. 四名成员分别完成采集、质量、建模与分析任务，共同审核设计，并交付报告、代码、PPT 和操作录屏。

## 1.5 研究范围与限制

以中国大陆工作地点的数字技术岗位为对象，核心来源先使用腾讯、网易。两名采集成员各验证一个额外企业官网，通过验收才纳入版本化来源范围。公司官网主要覆盖特定企业，公共平台也存在转载与字段缺口，因此本项目定位为“公开招聘样本分析”，不宣称为全行业普查。

不采个人简历、求职者行为、投递及录用数据；不分析实际就业人数、录用率或实际收入。不将缺失薪资补成零，不把岗位声明招聘人数等同于已实现招聘人数。单机离线批处理能够满足课程规模，实时流处理不是本题的必要条件。

## 1.6 方法与技术方向

采用 Kimball 的“确定业务过程→声明粒度→识别维度→识别事实”步骤，以一致性维度连接多类观察事实；按 ODS、DWD、DWS、ADS 分层，DIM 服务各业务层，AUDIT 提供批次与发布审计。

工具选择以主流、可维护和四人可交付为原则：现代 Python 采集与契约校验，Prefect 编排，dbt 管理 SQL 模型和测试，PostgreSQL 存储，Superset 展示。PostgreSQL 和 SQL 是现役主流分析基础，不因技术历史长就属于过时方案。版本、兼容性验证和不采用分布式集群的原因见第 5 章。

## 1.7 本章答辩要点

应讲清“谁需要这些分析、现有信息为什么难直接使用、自主采集及数仓分别解决什么问题、结论适用于什么范围”。本阶段只展示真实试采证据和设计目标，不展示未经计算的业务排名或增长结论。
