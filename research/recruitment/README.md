# 招聘选题真实试采与可行性报告

测试时间：2026-10-29 22 时至 2026-10-30 00 时（北京时间）。这是选题验证，不是已完成的数仓系统。只访问公开岗位信息，没有登录、投递简历、收藏岗位或访问个人简历。

## 1. 结论与选题建议

**招聘方向具备小规模技术可行性，建议以企业官方招聘网站为主，围绕岗位需求、技能结构和地区分布建设数仓。薪资不宜作为核心指标。** 腾讯、网易的列表、第二页、第十页、详情和间隔约 100 分钟后的再次查询均成功；国家大学生就业服务平台可读取前两页及详情，但第十页明确要求登录，不能作为无登录全量采集主来源。

推荐待定题目：《数字技术岗位需求与技能结构分析数仓系统的设计与实现》。当前样本还含游戏艺术、策划等非技术岗位，正式范围需先定义技术岗位分类，再筛选、人工核对。关键词“数据”也可能匹配公司名称或职责，不能直接认定所有结果都是数据技术岗位。

本次数据来自 Python 对公开网页及其公开 JSON 查询接口的主动请求，不是下载别人整理的招聘数据集。JSON 接口采集也是网络采集，但报告应如实说明，不能把接口请求描述成复杂网页逆向。工作量应来自多源适配、持续采集、版本管理、去重、文本处理和质量验证。

## 4. 发现的真实质量问题与工作量

### 4.1 同岗多渠道发布

就业平台 20 条列表样本中，“重庆一路好棋网络科技有限公司＋市场调研及数据整合＋重庆”出现 14 个不同岗位 ID，发布来源为不同高校；另一个“数据采集工程师”出现 2 个不同 ID。

这是疑似转载分组，尚未逐条核对完整正文，不能自动判定全部相同并删除。设计需要区分“来源发布记录”和“归并后的岗位”，保留每条来源及归并依据。招聘人数不能跨转载简单相加。

### 4.2 结构化字段与正文冲突

网易岗位 79623 的结构化学历为“大专”，任职要求正文却写本科以上。两者均保留，记录冲突，不静默选一个覆盖另一个。这个问题可形成明确的数据质量规则及人工审核流程。

### 4.3 一条记录包含多个岗位

独立发现的就业平台“技术类,研究类”记录是网易有道校园招聘简章，正文包括多个岗位，页面显示招聘 150 人。它不能直接等同于单一岗位，更不能把 150 人分配给其中某一个技术方向。应识别为招聘公告或综合职位，分类保存或排除于岗位级核心指标。

### 4.4 文本、时间与状态

- HTML 页面包含隐藏的投递弹窗、推荐岗位、公司介绍。当前详情演示只抽取“职位详情”到“扫码快速投递简历”之间的正文，避免把弹窗里的企业名称误认为当前招聘企业。
- 同一列表约 100 分钟后已发生变化，说明按页码追加可能漏抓或重复。后续应按来源 ID 去重、重叠扫描，并保存快照。
- 来源更新时间不是首次发布时间，更不是本系统首次发现时间。必须分列保存。
- 列表暂时不出现不能直接认定岗位已关闭。下架判断需要完整扫描、失败状态和连续缺失策略。
- 技能词典演示已能从正文匹配 Python、SQL、MySQL、Redis、Oracle 等；它仅证明信息可提取，不是已验证的技能识别模型。必须进一步区分职责、必需、优先及否定语境。

## 5. 做数仓的实际意义

服务对象以学生求职、课程培养和就业指导为主，在样本边界内回答：

1. 不同岗位类别、地区和企业需要哪些技术技能及技能组合？
2. 初级、实习、社会招聘岗位的学历与经验要求有何差异？
3. 持续采集期间，哪些岗位类别新增或调整较多？
4. 哪些来源重复发布多、字段冲突多，如何避免把转载误读为需求增长？
5. 在明确披露薪资的去重样本中，薪资区间如何分布？该项是补充分析。

当前主要验证了两家大型互联网企业和就业平台中的 6 家企业，不代表全国劳动市场。职位发布数不等于招聘人数或实际录用人数；招聘薪资不等于实际收入；技能共现不意味着掌握某技能必然带来高薪。

维度建模方向可考虑“来源发布事实、岗位观察快照、岗位技能关联”，共享日期、来源、企业、地区、岗位类别、学历和经验等维度。此处仅为可行性方向；定题后必须先按 PPT 模板完成需求、概念、逻辑、物理设计，再实现 ODS—DWD—DWS—ADS。

## 6. 还没有验证的内容

- 全量采集、持续多日运行、调度、自动重试、下架判定均未完成。
- 未取得历史完整招聘快照，不能凭当前更新时间重建过去需求趋势。
- 尚未完成多个来源之间同一岗位的精确匹配。
- 尚未确认其他企业官方招聘入口的可采性；扩展到更多企业是下一阶段任务，不是已完成成果。
- 没有登录就业平台，也没有绕过验证码、登录要求或限流。
- robots 路径在腾讯跳转 404 页面，在网易返回应用壳，在就业平台返回错误页，均不能解读为明确的批量采集授权。正式扩量前仍需核对网站使用规则并控制频率。
- 首轮门户首页连通性初探只在执行输出中，未计入 36 条持久化日志；原始报错中腾讯 CDN 脚本为 403，不影响已成功的公开岗位接口验证。

## 7. 文件与复现

- `probe.py`：标准库低频请求与响应保存，包含 GET 和只读查询 POST，非生产级爬虫。
- `requests.jsonl`：真实请求时间、地址、参数、响应状态、哈希及原始文件位置。
- `raw/`：原始响应、HTML、公开脚本和提取文本，仅原试采机器留存，Git 忽略。
- `analyze.py`：离线回读校验、有限字段规范化、疑似重复分组及技能词典演示。
- `samples.json`：本机生成的 108 条来源岗位记录及字段来源信息，保留原始描述，Git 忽略；GitHub 阅读汇总请查看 `summary.json`。
- `summary.json`：分页结果、详情验证、字段覆盖和疑似重复分组。
- `reproduce.py`：有边界的复采入口，默认仅再次查询每个主来源一页，不自动全量抓取。

在项目根目录运行（Python 3.12，标准库，无需安装依赖）：

```powershell
python research/recruitment/analyze.py
python research/recruitment/reproduce.py
```

`analyze.py` 不联网，要求日志所引用的原始文件已在本机存在。GitHub 仓库仅提供原试采日志及汇总，不含原始正文；新克隆不能直接对历史日志运行分析，应先取得原试采批次的原始文件。`reproduce.py` 可独立验证当前两家企业入口，会追加实际请求日志并保存新响应；它不会补齐历史原始文件。再次完整分析后统计将更新，本报告为本轮固定结论，需要同步修订数字。原始正文不上传 GitHub。
